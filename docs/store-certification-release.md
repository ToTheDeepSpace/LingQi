## 已实现

- 店家认证商品 `store_certification`：9000分，付款后提交私密证明，人工批准才永久认证（暂行）并获11个名额。
- 加购商品 `store_code_pack`：9000分，每包11个。重复点击复用待付包，到账事务内发放，重复回调不重复发码。
- 个人认领、首次委托条、联系方式解锁仍为900分；历史888分实付记录不改。
- DM用码免付9元，须手机号验证、本人证明、同意绑定发码店家；提交时预留，批准时一次性消耗并绑定关系。
- 驳回保留同账号同档案的预留，允许免费补材料；离职不返还名额。其他店家关系未结束时不能用码。
- 新管理页：我的 → 店家认证与名额；原店家详情也可进入。后台认领审核展示付费/用码来源，公开店家列表可撤销认证。
- 旧独立DM/店家身份认证入口导向档案认领，后端拒绝旧入口直接取得认证。实名认证不变。

## 关键实现差异与安全性

支付回调/批准时分配11个无明文的名额槽位。经营者点击“领取”时才生成随机码，数据库和审计日志仅存SHA256摘要和尾号。领取响应只出现一次，不缓存；遗失的未使用码可重置。并不是在回调中生成随后无法取回的明文。

支付确认、退款、认领提交/批准、领码/重置都在事务中获取同一权益锁，再锁业务行；批次及槽位有唯一约束。退款或管理员撤销会吊销未使用/预留码，已使用仍保持消耗。撤销时恰好到账的加购记录到账事实，但保持批次撤销，需管理员核对退款，不恢复权益。

新表启用RLS，普通数据库角色没有读写权限；应用角色只授予SELECT/INSERT/UPDATE，沿用生产应用角色的既有BYPASSRLS配置。私密接口校验所有权和有效认证，后台撤销额外校验管理员。新模块已纳入服务端写接口安全分类测试。
